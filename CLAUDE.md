# STAT 359 Project

## Overview

This project evaluates LLM performance on **Named Entity Recognition (NER)** using the
[NuNER](https://huggingface.co/datasets/numind/NuNER) dataset under two settings:

1. **Training-free (zero-shot / few-shot prompting)** — baseline LLM capabilities without parameter updates
2. **Small-scale SFT fine-tuning** — QLoRA via Unsloth, studying how much domain-specific data is needed

The core research question: *How many domain-knowledge samples are needed to achieve good NER performance via SFT?*

## Dataset: numind/NuNER

The training set is split into two subsets by `preprocessing.ipynb`:

- **Generic samples** — general-purpose entity types (Person, Organization, Location, Date, …)
- **Domain (tech) samples** — technology-specific entity types (Software, Algorithm, Programming Language, Database, Framework, …)

Splits saved under `data/`:
- `train.parquet`, `validation.parquet`, `test.parquet` — 80/10/10 of full NuNER
- `generic_train.parquet` — generic NER samples from train
- `domain_train.parquet` — tech-domain NER samples from train

## Experiment Design

### Training Configurations (per model)

| # | Name | Generic N | Domain N | Sequential |
|---|------|-----------|----------|------------|
| 1 | Zero-shot baseline | — | — | — |
| 2 | Few-shot baseline (5-shot) | — | — | — |
| 3–6 | Generic only | 0.5k / 1k / 2k / 4k | 0 | No |
| 7–10 | Domain only | 0 | 0.5k / 1k / 2k / 4k | No |
| 11–14 | Generic → Domain | 0.5k / 1k / 2k / 4k | 0.5k / 1k / 2k / 4k | Yes (phase 1 then phase 2) |

**Total: 14 configs × 2 models = 28 experiment runs**

### Evaluation Metric
**Entity-level micro F1** — exact match on (entity text, entity type) pairs, case-insensitive.

## Tech Stack

- **Language:** Python 3.10+
- **Fine-tuning:** [Unsloth](https://github.com/unslothai/unsloth) (QLoRA / 4-bit), PEFT
- **Framework:** HuggingFace Transformers + TRL (SFTTrainer)
- **Notebooks:** Google Colab (GPU: T4 minimum, A100 recommended)
- **Evaluation:** Custom entity-level F1 (exact match)

## Running Order

1. **`preprocessing.ipynb`** — generate all splits under `data/` (CPU is fine)
2. **`finetune_qwen25_7b.ipynb`** — run on Colab GPU; results → `results_qwen25_7b.csv`
3. **`finetune_qwen35_9b.ipynb`** — run on Colab GPU; results → `results_qwen35_9b.csv`
4. Compare the two CSVs to study data-scaling and domain-transfer effects

Each fine-tuning notebook resumes automatically if interrupted (completed experiments are
detected from the CSV and skipped).
